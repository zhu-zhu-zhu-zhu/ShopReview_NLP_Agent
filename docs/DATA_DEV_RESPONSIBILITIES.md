# Data Developer Responsibilities

> 角色：数仓开发 / Data Warehouse Development  
> 工作分支：`data-dev`

## ODS、DWD、DWS 是什么

### ODS：贴源层

ODS 尽量保留源数据的原始结构，用于追溯、重新处理和源端对账。本项目计划为评论 JSONL 和商品元数据 JSONL 分别建立 ODS 表。ODS 不负责给出业务结论。

### DWD：清洗明细层

DWD 把 ODS 数据整理为可分析的明细，例如统一字段、解析时间、处理空文本、标记重复记录、生成评分弱标签，并通过 `parent_asin` 关联评论与商品元数据。清洗规则和被过滤的数据量必须可解释。

### DWS：汇总服务层

DWS 按明确粒度和口径生成情感总览、趋势、商品、店铺、真实购买、用户行为、方面、差评原因和告警等汇总结果。Agent、API 和前端应使用经过验证的 DWS 输出，而不是直接读取原始 JSONL。

## 我需要交付什么

- 两份源文件的只读结构检查记录；
- 可复现的 100 行和 10,000 行开发样本；
- 数据名片与经过验证的数据字典；
- HDFS 路径、加载规则和文件核验记录；
- ODS、DWD、DWS 建表与处理 SQL；
- 数据质量检查、行数对账和异常记录；
- 面向 Agent/前端的数据导出与字段合同；
- 每阶段的命令、结果、截图和状态文档。

所有交付应区分“计划”“已执行”和“已验证”，不能用占位内容冒充运行结果。

## 必须提供给 Agent 开发的内容

- 可查询的 DWS 表或受限 API/JSON 输出；
- 每个字段的类型、含义、粒度、时间窗和空值规则；
- 情感计数、比例及分母定义；
- 商品情感、方面统计、差评原因和告警结果；
- 代表性评论样本的来源与使用限制；
- 最小可用的合成测试夹具；
- 口径变更、字段变更和数据质量状态通知。

Agent 不应直接读取原始 JSONL、重算数仓指标或执行不受限 SQL。

## 必须保存的验证证据和截图

- 本地原始文件的名称、大小和只读路径；
- HDFS 文件路径、大小和上传结果；
- ODS 源端行数与加载行数对账；
- DWD 输入、输出、过滤和重复数量；
- 评论与元数据的 `parent_asin` 关联率；
- DWS 总计与 DWD 明细汇总对账；
- 关键 SQL、执行时间和抽样查询结果；
- 异常、修复过程和复核结果；
- Git 分支、提交记录和安全跟踪检查。

截图应包含命令、关键结果和必要上下文，但不得暴露密钥、凭据或完整原始数据。

## 我不应修改什么

- `main`、`agent-dev`、`nlp-model-dev` 或 `web-front-dev` 上的成员工作；
- 原始实施框架说明书；
- 原始 JSONL 文件及其存放位置；
- NLP 模型、Agent 提示词和编排、React 前端等其他成员负责的模块；
- `.env`、API Key、密码、Token 或其他凭据；
- 未经团队确认的数据合同和公共字段口径。

跨模块确需修改时，应先沟通负责人并通过团队约定的审查流程处理。

## Daily Git Checklist

1. `git checkout data-dev`
2. `git pull --ff-only origin data-dev`
3. 一次只处理一个小型数仓任务。
4. 只运行与当前任务相关的验证。
5. 提交前逐项检查发生变化的文件。
6. 不暂存原始数据或 `.env`。
7. 使用范围明确的提交信息进行 commit。
8. 只推送到 `data-dev`。
9. 数据合同发生变化时及时通知 Agent 开发人员。

提交前还应确认：当前分支正确、工作树中没有无关修改、暂存区不含 JSONL/`data/raw`/密钥，并保存必要的验证输出。
